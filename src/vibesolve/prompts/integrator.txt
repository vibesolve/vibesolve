When you generate your tests, create a separate solverConfigTest.xml and use FULL_ASSERT. Use that solverConfigTest.xml for testing, and leave your solverConfig.xml for Main AND for the running Quarkus application.
Always create solverConfigTest.xml as a file, never put its content inside of a String and then try to load that. Whenever there's a solverConfig xml it always means a new file.

**Environment mode rules — read carefully, this matters:**
- `solverConfig.xml` is the PRODUCTION config. It uses `<environmentMode>REPRODUCIBLE</environmentMode>`. Quarkus at runtime (i.e. the `SolverResource` REST layer) MUST use this file — FULL_ASSERT is far too slow for real solving and must never be active when Quarkus serves requests.
- `solverConfigTest.xml` is the TEST config. It uses `<environmentMode>FULL_ASSERT</environmentMode>`. It is activated ONLY under the Quarkus `%test` profile and ONLY by the standalone `SolverIntegrationTest` via `SolverFactory.createFromXmlResource("solverConfigTest.xml")`.
- How Quarkus picks the right file: `application.properties` MUST contain `quarkus.timefold.solver.solver-config-xml=solverConfig.xml` (production default) AND `%test.quarkus.timefold.solver.solver-config-xml=solverConfigTest.xml` (only active under the test profile). This is the mechanism — do not invent alternatives.
- Termination lives ONLY in `solverConfig.xml` / `solverConfigTest.xml` (`<secondsSpentLimit>15</secondsSpentLimit>`). NEVER duplicate termination in `application.properties` via `quarkus.timefold.solver.termination.*` — Timefold will throw `IllegalArgumentException: conflicting spentLimit` at startup.

## 3. Auto-Discovery (Zero XML)

With the Quarkus extension, Timefold automatically discovers:

| What | How |
|---|---|
| `@PlanningSolution` class | Classpath scan |
| `@PlanningEntity` classes | Classpath scan |
| `ConstraintProvider` implementation | Classpath scan (exactly one) |
| Planning variables, value ranges | Annotations on entity/solution |

Termination and environment mode are configured in `solverConfig.xml`, referenced by `application.properties` via `quarkus.timefold.solver.solver-config-xml=solverConfig.xml`.

## 4. Injectable Beans

Quarkus auto-creates and manages these beans. Inject with `@Inject`:

```java
import jakarta.inject.Inject;

@Inject
SolverManager<EmployeeSchedule, String> solverManager;

@Inject
SolutionManager<EmployeeSchedule, HardSoftScore> solutionManager;

@Inject
SolverFactory<EmployeeSchedule> solverFactory;     // rarely needed directly

@Inject  // in test classes
ConstraintVerifier<EmployeeSchedulingConstraintProvider, EmployeeSchedule>
        constraintVerifier;
```

| Bean | Purpose | When to use |
|---|---|---|
| `SolverManager<Solution, ProblemId>` | Async solving, manages thread pool | **Always use this in REST endpoints** |
| `SolutionManager<Solution, Score>` | Score analysis, explanation | Score breakdown, constraint analysis |
| `SolverFactory<Solution>` | Create Solver instances manually | Rarely — only for custom thread management |
| `ConstraintVerifier<Provider, Solution>` | Unit test constraints | Test classes only |

## 5. MANDATORY REST Resource Template

You MUST generate `SolverResource.java` exactly matching this structure.
Substitute the placeholders:
- `{{SOLUTION_CLASS}}` — the `@PlanningSolution` class name (e.g. `EmployeeSchedule`)
- `{{PACKAGE}}` — the base package (e.g. `com.example.scheduling`)

**Base path is ALWAYS `"api"`** — do NOT use a domain-specific noun like `"schedules"`, `"timetables"`, or `"route-plans"`. The class-level `@Path("api")` is fixed across every generated project.

**Every endpoint has its own named sub-path** — `/all`, `/generate`, `/solve`, `/solution/{jobId}`, `/status/{jobId}`, `/stop/{jobId}`, `/analyze`. NEVER leave an endpoint mapped to the bare base path (e.g. `GET /api` with no sub-path, or `POST /api` with no sub-path) — every method must declare its own `@Path("<name>")`.

All projects use `HardSoftScore`. The score type is fixed — do not use any other score type.

**CRITICAL: ALL imports below are required. `SolverStatus` is a SEPARATE TOP-LEVEL CLASS — do NOT reference it as `SolverManager.SolverStatus` (that nested class does not exist and will cause a compile error).**

```java
package {{PACKAGE}}.rest;

import ai.timefold.solver.core.api.score.analysis.ScoreAnalysis;
import ai.timefold.solver.core.api.score.buildin.hardsoft.HardSoftScore;
import ai.timefold.solver.core.api.solver.ScoreAnalysisFetchPolicy;
import ai.timefold.solver.core.api.solver.SolutionManager;
import ai.timefold.solver.core.api.solver.SolverManager;
import ai.timefold.solver.core.api.solver.SolverStatus; // ← standalone top-level class
import {{PACKAGE}}.data.DataGenerator; // adjust sub-package if DataGenerator lives elsewhere
import jakarta.inject.Inject;
import jakarta.ws.rs.Consumes;
import jakarta.ws.rs.DELETE;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.POST;
import jakarta.ws.rs.PUT;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.PathParam;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.QueryParam;
import jakarta.ws.rs.WebApplicationException;
import jakarta.ws.rs.core.MediaType;
import jakarta.ws.rs.core.Response;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.util.Collection;
import java.util.UUID;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ConcurrentMap;

@Path("api")
public class SolverResource {

    private static final Logger LOGGER = LoggerFactory.getLogger(SolverResource.class);

    private final SolverManager<{{SOLUTION_CLASS}}, String> solverManager;
    private final SolutionManager<{{SOLUTION_CLASS}}, HardSoftScore> solutionManager;

    // TODO: Without any "time to live", the map may eventually grow out of memory.
    private final ConcurrentMap<String, Job> jobIdToJob = new ConcurrentHashMap<>();

    // Workaround to make Quarkus CDI happy. Do not use.
    public SolverResource() {
        this.solverManager = null;
        this.solutionManager = null;
    }

    @Inject
    public SolverResource(SolverManager<{{SOLUTION_CLASS}}, String> solverManager,
            SolutionManager<{{SOLUTION_CLASS}}, HardSoftScore> solutionManager) {
        this.solverManager = solverManager;
        this.solutionManager = solutionManager;
    }

    /** List all submitted job IDs. */
    @GET
    @Path("all")
    @Produces(MediaType.APPLICATION_JSON)
    public Collection<String> listAll() {
        return new ArrayList<>(jobIdToJob.keySet());
    }

    /**
     * Generate a sample unsolved problem using DataGenerator.
     * Use this to obtain valid JSON that can be POSTed directly to POST /api/solve.
     */
    @GET
    @Path("generate")
    @Produces(MediaType.APPLICATION_JSON)
    public {{SOLUTION_CLASS}} generate() {
        // Use medium-sized valid arguments suitable for a representative sample problem
        return new DataGenerator().generate(/* valid medium-dataset arguments */);
    }

    /** Submit a problem to start solving asynchronously; returns a jobId. */
    @POST
    @Path("solve")
    @Consumes(MediaType.APPLICATION_JSON)
    @Produces(MediaType.TEXT_PLAIN)
    public String solve({{SOLUTION_CLASS}} problem) {
        String jobId = UUID.randomUUID().toString();
        jobIdToJob.put(jobId, Job.ofSolution(problem));
        solverManager.solveBuilder()
                .withProblemId(jobId)
                .withProblemFinder(jobId_ -> jobIdToJob.get(jobId).solution)
                .withBestSolutionEventConsumer(event -> jobIdToJob.put(jobId, Job.ofSolution(event.solution())))
                .withExceptionHandler((jobId_, exception) -> {
                    jobIdToJob.put(jobId, Job.ofException(exception));
                    LOGGER.error("Failed solving jobId ({}).", jobId, exception);
                })
                .run();
        return jobId;
    }

    /** Get the best solution found so far (solving may still be in progress). */
    @GET
    @Path("solution/{jobId}")
    @Produces(MediaType.APPLICATION_JSON)
    public {{SOLUTION_CLASS}} getBestSolution(@PathParam("jobId") String jobId) {
        {{SOLUTION_CLASS}} solution = getSolutionAndCheckForExceptions(jobId);
        solution.setSolverStatus(solverManager.getSolverStatus(jobId));
        return solution;
    }

    /** Get the current solver status for a job (lightweight — no solution payload). */
    @GET
    @Path("status/{jobId}")
    @Produces(MediaType.APPLICATION_JSON)
    public SolverStatus getStatus(@PathParam("jobId") String jobId) {
        getSolutionAndCheckForExceptions(jobId); // validates job exists and re-throws solver exceptions
        return solverManager.getSolverStatus(jobId);
    }

    /**
     * Stop solving early, return the best solution found so far, and gracefully
     * remove the job from the in-memory map so it does not leak.
     */
    @DELETE
    @Path("stop/{jobId}")
    @Produces(MediaType.APPLICATION_JSON)
    public {{SOLUTION_CLASS}} stopSolving(@PathParam("jobId") String jobId) {
        solverManager.terminateEarly(jobId);
        {{SOLUTION_CLASS}} solution = getBestSolution(jobId); // fetch before removal; throws 404 if missing
        jobIdToJob.remove(jobId); // graceful cleanup — no-op if already absent
        return solution;
    }

    /** Analyze the score of a given solution without solving. */
    @PUT
    @Path("analyze")
    @Consumes(MediaType.APPLICATION_JSON)
    @Produces(MediaType.APPLICATION_JSON)
    public ScoreAnalysis<HardSoftScore> analyze({{SOLUTION_CLASS}} problem,
            @QueryParam("fetchPolicy") ScoreAnalysisFetchPolicy fetchPolicy) {
        return fetchPolicy == null
                ? solutionManager.analyze(problem)
                : solutionManager.analyze(problem, fetchPolicy);
    }

    private {{SOLUTION_CLASS}} getSolutionAndCheckForExceptions(String jobId) {
        Job job = jobIdToJob.get(jobId);
        if (job == null) {
            throw new WebApplicationException("No solution found for jobId: " + jobId,
                    Response.Status.NOT_FOUND);
        }
        if (job.exception != null) {
            throw new WebApplicationException(job.exception.getMessage(),
                    Response.Status.INTERNAL_SERVER_ERROR);
        }
        return job.solution;
    }

    private record Job({{SOLUTION_CLASS}} solution, Throwable exception) {
        static Job ofSolution({{SOLUTION_CLASS}} solution) { return new Job(solution, null); }
        static Job ofException(Throwable e) { return new Job(null, e); }
    }
}

**`setSolverStatus()` requirement:** The `@PlanningSolution` class MUST have a `solverStatus` field so the REST resource can set it before returning. If the domain model agent did not add it, add it yourself:
```java
import ai.timefold.solver.core.api.solver.SolverStatus;

// Inside the @PlanningSolution class:
@Getter @Setter
private SolverStatus solverStatus;
```
Do NOT add `@JsonIgnore` — clients need to see `solverStatus` in REST responses to know whether solving is still in progress.

**Key rules:**
- `solverManager.solveBuilder()...run()` is the ONLY pattern to use in REST. Never call `getFinalBestSolution()` from a REST handler.
- `SolverStatus` is always a separate import — never `SolverManager.SolverStatus`.
- `ConcurrentHashMap` is always initialized inline on the field declaration.
- The no-arg constructor (CDI workaround) is always required alongside the `@Inject` constructor.
- The `generate` endpoint MUST call `DataGenerator.generate(...)` with valid arguments that produce a medium-sized, realistic unsolved problem, so the returned JSON is guaranteed to be valid input for `POST /api/solve`.
- The `stop` endpoint MUST call `solverManager.terminateEarly(jobId)`, fetch the best solution, and THEN `jobIdToJob.remove(jobId)` so the in-memory map does not leak stopped jobs. `ConcurrentMap.remove` is a graceful no-op if the key is already absent.

## 6. SolverManager API

```java
// Simple solve (returns SolverJob)
SolverJob<Solution, ProblemId> job = solverManager.solve(problemId, problem);
Solution best = job.getFinalBestSolution();  // blocks until done; throws InterruptedException, ExecutionException

// Builder pattern (recommended for REST endpoints)
solverManager.solveBuilder()
    .withProblemId(jobId)
    .withProblemFinder(jobId_ -> jobIdToJob.get(jobId).schedule)         // fetch problem from store
    .withBestSolutionEventConsumer(event -> saveSolution(event.solution())) // called on improvement
    .withExceptionHandler((jobId_, ex) -> handleError(jobId_, ex))       // called on failure
    .run();

// Check status
SolverStatus status = solverManager.getSolverStatus(problemId);
// SolverStatus values: NOT_SOLVING, SOLVING_ACTIVE, SOLVING_SCHEDULED

// Stop early
solverManager.terminateEarly(problemId);
```

The problem ID (`String`, `Long`, `UUID`) uniquely identifies a solving job. Use it for all subsequent operations.

### Classes and methods that do NOT exist — never generate these

The following classes and methods do NOT exist in the Timefold API and will cause compilation errors:
- `SolverManagerFactory` — does not exist; inject `SolverManager<Solution, Id>` directly via `@Inject`
- `SolverJobId` — does not exist
- `job.whenTerminated(...)` — does not exist
- `solverManager.getSolverStatus()` returning a `boolean` — wrong return type (it returns `SolverStatus`)
- `solverManager.getSolverJob(id)` — does not exist; store solutions in the `jobIdToJob` map via `withBestSolutionEventConsumer`
- `.withProblem(problem)` on solveBuilder — does not exist; use `.withProblemFinder(jobId_ -> ...)` instead
- `.withBestSolutionConsumer(solution -> ...)` on solveBuilder — does not exist; use `.withBestSolutionEventConsumer(event -> event.solution())` instead
- `SolverManager.SolverJobListener` — does not exist; there is no nested `SolverStatus` class inside `SolverManager` either
- `solverManager.solveAsync(...)` — does not exist; use `solveBuilder()...run()` for async solving
- `complement(...)` in constraint streams — does not exist
- `SolverManager.SolverStatus` — does NOT exist as a nested class. `SolverStatus` is a standalone top-level class: `import ai.timefold.solver.core.api.solver.SolverStatus;`

Correct pattern for synchronous Main class usage:
```java
SolverJob<MySchedule, String> job = solverManager.solve("main", schedule);
MySchedule solution = job.getFinalBestSolution();
```
